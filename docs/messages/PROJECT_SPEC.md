# PROJECT_SPEC —— Jason Blog Messages

> 来源：管理员 2026-11-15 提供的项目规范（原文）。本文件是**要求登记表**，逐条保留约束与验收口径；
> 实现细节见同目录的 `AUDIT_REPORT.md` / `ARCHITECTURE_PROPOSAL.md` / `DATABASE_PROPOSAL.md` / `SECURITY_REVIEW.md`。
> 任何与本文件冲突的实现都视为不合规。

- 项目：Jason Blog Messages（个人博客私信系统）
- 所属：Jason Blog / NotionNext（GitHub `666su/NotionNext`）
- 站点：`https://blog.20240606.xyz`
- 访客入口：博客右下角悬浮入口
- 管理员入口：`/admin/messages`
- 管理员认证：**复用现有 Jason Blog Admin**（不新建）
- 访客身份：免注册、免登录，靠私密会话链接
- 邮箱：选填
- 存储：优先复用现有基础设施，必要时新增
- 开发原则：**先审计 → 再设计 → 分阶段实施 → 逐阶段验收**

---

## 1. 背景与目标

访客希望：提问、反馈文章错误、交流经验、合作咨询、提改进建议、反馈网站问题、就某篇文章私人交流。
现状：缺少统一私人沟通渠道。

目标流程：访客点右下角入口 → 填昵称/邮箱(可选)/正文 → 发送 → 服务端建私密会话 → 返回专属链接 →
管理员登录 `/admin/messages` 查看并回复 → 访客用链接查看回复 → 继续双向交流。

## 2. 强制架构要求

**禁止**：独立私信网站；第二套博客项目；第二个 Vercel 项目；更换现有主题；新建管理员认证；私信内容存进 Notion 公开文章库；
私信内容公开显示；公开导航里加后台入口。

**必须**：复用现有仓库 / 域名 / 部署 / 管理员认证；在现有后台加私信模块；在现有博客加访客入口；
私信数据与公开内容隔离；私信 API 与管理员 API 严格权限控制。

## 3. 功能范围

### 3.1 第一期（v1）必须实现

**访客端**：右下角悬浮入口；私信窗口；昵称必填；邮箱选填；正文；发送；成功后生成私密会话链接；
查看历史对话；查看管理员回复；继续发送；复制链接；关闭/重开窗口（本次会话内不丢输入）。

**管理员端**：收件箱；新消息数；未读提示；会话列表；对话详情；回复；标记已读/未读/处理中/已解决；
归档；删除垃圾消息；搜索；按状态筛选；按时间排序。

**系统端**：私密会话凭证；安全身份验证；消息存储；权限控制；频率限制；防垃圾；长度限制；数据清理；
基础审计日志；安全错误处理。

### 3.2 第二期（v1 之后）

邮件通知、新消息提醒、图片/文件附件、自动分类、AI 辅助回复、垃圾自动识别、Telegram 通知。

### 3.3 第三期

SSE/WebSocket 实时、更完善的访客通知、附件管理、多管理员、会话分配、优先级。
**v1 不做复杂实时聊天。**

## 4. 访客端设计

### 4.1 入口

桌面右下角、移动端适配安全区；不遮挡正文/评论/导航；与桌宠兼容；**不得简单叠加多个悬浮按钮**（现有已占位的需先审计）；
点击展开窗口；动画简洁、性能可接受；支持开关与键盘操作；深浅色主题；关闭不丢当前输入（至少本次页面会话内）；
入口不得出现在公开导航。

### 4.2 窗口与字段

字段：昵称（必填 1–40）、邮箱（选填，基本格式，≤254）、正文（必填 1–5000）。
去首尾空白；拒绝空白；拒绝不合法数据；**前后端都校验**；长度可配置但不能只靠前端。

### 4.3 发送状态

必须覆盖：等待、发送中、成功、失败、网络异常、频率限制、内容不合法。
防重复提交：服务端用消息唯一 ID 或幂等请求标识。

### 4.4 成功页

展示"已发送给 Jason / 已创建专属私密会话 / 复制私密会话链接 / 请保存 / 无需注册登录"，
并**明确提示：链接即凭证，妥善保存，不要公开分享**。v1 不承诺邮箱找回。

### 4.5 历史会话

再次打开链接：验证凭证 → 取会话 → 展示历史与回复 → 可继续发送。
只展示当前会话；**修改会话 ID 不能读别人消息**。

## 5. 私密链接与访客身份（安全核心）

- **会话 ID 与访问凭证必须分离**；凭证 ≥32 字节密码学安全随机。
- **库里不存明文凭证**：存 `SHA-256(token + server_secret)` 或等效安全值。
- 凭证不得：明文入库、进普通日志、进错误追踪、被第三方 SDK 采集、被审计日志完整记录。
- 链接形态：`/message/{conversation_id}#{access_token}`；**凭证放 fragment 不放 query**。
- 兑换流程：读 fragment → HTTPS POST 专用兑换接口 → 校验 → 下发受限 HttpOnly Cookie
  （Secure、HttpOnly、SameSite=Lax 或更严、最小 Path、不设多余 Domain、独立 Cookie 名）→ 前端立即清除 fragment → 后续靠 Cookie。
- 兑换接口必须防重复滥用；**不得**把凭证写入 localStorage/sessionStorage；不得暴露给第三方脚本/统计 SDK。
- 刷新页面不得无故丢失当前对话。
- v1 不提供：按昵称/邮箱/猜测 ID 找回；不允许管理员用访客邮箱暴露其他会话。

## 6. 管理员后台

- 入口 `/admin/messages`，**复用现有会话**；不得新建第二套账号密码；不得把私信数据接口暴露给访客。
- 侧边栏按现有导航体系增加（以真实组件为准，不重写布局）。
- 收件箱：左侧列表（昵称、摘要、时间、未读、状态、是否留邮箱），右侧详情（完整历史、发送者、时间、回复框、状态管理）。
- 状态：`unread / read / processing / resolved / archived / spam`。
  - 会话状态与消息已读状态**分开存**；
  - 访客发新消息可自动重开已解决会话；
  - 管理员阅读后更新消息已读时间；
  - 归档不删除消息；垃圾消息有独立筛选。
- 回复流程：校验会话 → 校验内容 → 生成消息 ID → 保存 → 更新会话时间 → 更新未读 → 记操作日志。v1 不发邮件。
- 管理员操作至少：回复、已读、未读、处理中、已解决、重开、归档、标垃圾、删除（**二次确认**；
  删除必须按保留策略真正处理数据，不能只隐藏按钮）。

## 7. 数据设计（逻辑模型）

`conversations`：id、visitor_name、visitor_email、access_token_hash、status、created_at、updated_at、last_message_at、resolved_at、archived_at。
`messages`：id、conversation_id、sender_type、content、created_at、read_at、client_request_id（唯一约束）。
`conversation_access_logs`（可选）：id、conversation_id、action、created_at（**不存凭证**）。
`message_rate_limits`：按实际方案实现（会话内、来源、兑换尝试）。
索引至少：messages.conversation_id、messages.created_at、conversations.status、conversations.updated_at、conversations.last_message_at。
时间统一 UTC 存储，前端按本地时区显示。

## 8. API

**访客**：`POST /api/messages/conversations`（创建，返回链接：凭证仅此一次）、
`POST /api/messages/access/exchange`（兑换 cookie）、`GET /api/messages/conversations/{id}`、
`POST /api/messages/conversations/{id}/messages`、`GET /api/messages/conversations/{id}/messages`。

**管理员**：`GET /api/admin/messages/conversations`（筛选/分页/搜索/排序）、
`GET /api/admin/messages/conversations/{id}`、`POST …/{id}/messages`、`PATCH …/{id}`、`DELETE …/{id}`。

**通用**：HTTPS；服务端校验；体积限制；限流；防注入/XSS/CSRF；不返回内部错误；不暴露凭证；
不暴露他人消息；不允许公开查询全部；未授权不得调管理员接口。

## 9. 防滥用

- 限流初值：同会话 5 条/分、30 条/小时；同来源创建次数受限；兑换接口限流。数值可调。
- 不能只靠 IP（同 IP 可能多人）；需用 IP 时用短期不可逆派生标识，避免持久化明文 IP。
- Honeypot 隐藏字段：被填写则拒绝或标垃圾。
- 验证码：v1 不强制；高风险时启用；必须服务端校验。
- 内容：限长、过滤非法控制字符、拒绝大量重复、防 HTML 注入、前端安全文本渲染、链接安全展示。
- **v1 只支持纯文本**，不支持 HTML/Markdown 渲染/图片/附件。

## 10. 隐私与数据

- 邮箱选填；不填也能用；仅用于未来经同意的联系/通知；v1 不据此发任何自动邮件；不得公开显示。
- 私信正文：仅访客本人与管理员可见；不公开、不进文章、不进评论、不进搜索索引、不发第三方分析、不写不必要日志。
- 保留：正常长期（管理员可删）；垃圾可较短；安全日志仅必要期限；删除会话要连带处理关联数据。
- 页面头：`X-Robots-Tag: noindex, nofollow, noarchive`、`Referrer-Policy: no-referrer`，并按能力设置 CSP。
  **noindex 不是权限控制**；私密页不得用公开 CDN 缓存策略。

## 11. 技术架构

- 优先兼容：NotionNext、GitHub、Vercel、Cloudflare、Notion、Twikoo；优先复用后台 API / Session / 存储；未经审计不得重复建库或认证。
- 存储顺序：先评估现有库 → 不合适再评估 D1。若用 Worker + D1：Worker 负责 API、D1 存数据、Worker 鉴权、后台经受保护 API 访问、数据库不暴露给浏览器。
  **不能假设 Vercel Functions 能直接用 D1 Binding。**
- 前端：私信组件独立开发，不改大量主题文件，懒加载，不影响首页性能；后台页复用现有布局。
- 实时：v1 不用 WebSocket；可手动刷新 / 合理轮询 / 聚焦时刷新；管理员 15–30s 可配；离开页面停止轮询；访客端不常驻轮询；避免过频查询。

## 12. UI/UX

风格与现有主题一致：简洁、现代、技术博客风、层级清晰、深浅色、桌面与移动适配；不另造视觉系统。
访客端需覆盖：欢迎提示、表单、发送中、失败、复制链接、保存提醒、历史、继续发送、空状态、网络错误、会话失效。
管理员端需覆盖：列表、未读数、摘要、时间、状态、气泡、回复框、发送、快捷键（可选）、搜索、筛选、删除确认、移动端。
回复后及时更新未读与会话列表。

## 13. 开发阶段（必须逐阶段验收）

| 阶段 | 内容 | 要求 |
| --- | --- | --- |
| **Phase 0** | 只读审计 | 输出 `AUDIT_REPORT / ARCHITECTURE_PROPOSAL / DATABASE_PROPOSAL / SECURITY_REVIEW`；**禁止改代码/主题/认证/数据库/配置/部署/Notion**；完成后停止等确认 |
| Phase 1 | 数据与后端基础 | 建表/索引、创建会话、凭证生成与哈希、兑换、HttpOnly Cookie、访客发/查消息、管理员列表/详情/回复/状态、限流、错误日志 |
| Phase 2 | 访客端组件 | 悬浮按钮、窗口、表单与校验、发送与状态、链接生成与复制、链接打开、兑换、历史、继续发送、移动端、桌宠兼容 |
| Phase 3 | 管理员页 | `/admin/messages`、侧边栏、全部私信、未读数、筛选、搜索、详情、回复、已读/未读、处理中/已解决、归档、垃圾、删除确认、移动端；复用现有认证 |
| Phase 4 | 安全与异常 | 凭证安全、越权、Cookie、CSRF、XSS、重复提交、限流、垃圾、无效凭证、过期 Cookie、链接丢失、数据库异常、网络中断、权限隔离 |
| Phase 5 | 部署验收 | 备份、检查工作区/Commit、建分支、生产构建、权限与移动端测试、博客回归、检查环境变量与数据库备份、预览部署与验证、管理员确认后上生产、最终报告 |

每阶段完成后必须汇报：改动的文件、新增依赖、新增环境变量、数据库变更、API 变更、测试结果、
是否影响现有博客、如何回滚，然后等待确认。

## 14. 验收标准（摘要）

- 访客端：入口/表单/邮箱选填/非法邮箱/空消息/超长/正常发送/复制链接/打开链接/刷新保留/关闭不丢/网络异常。
- 私密链接：正确凭证通、错误凭证拒、改 ID 不能跨会话、删凭证不可再授权、伪造 Cookie 拒、Cookie 过期要重验、
  跨浏览器凭链接可访问、fragment 兑换正常、凭证不入普通日志。
- 管理员：访问正常、未登录拒绝、未登录 API 401/403、查看、回复、访客可见、四种状态、归档、删除二次确认。
- 安全：SQL 注入、XSS、CSRF、IDOR、暴力破解、刷量、重放、凭证泄露、Cookie 属性、未授权管理员 API、缓存泄露。
- 回归：首页、文章、分类、标签、搜索、Twikoo、导航、桌宠、统计、移动端、Vercel 构建、现有 Admin 全部正常；
  **私信出问题不得影响博客公开访问**。

## 15. 性能

独立模块、按需加载、不阻塞首屏、不引大量依赖、不用 WebSocket、消息分页、历史按需、索引用上、
管理员轮询合理间隔、访客未开窗不请求、错误重试有上限。

## 16. 备份与删除

可独立备份；迁移有回滚；删除正确处理关联消息；删除失败不留不一致；垃圾可单独管理；
不得无故清理正常私信；私信不得备份到公开仓库；备份文件需访问保护；软删要有彻底删除机制。

## 18. 最高优先级

保护访客隐私 → 保护私信内容 → 防会话越权 → 保护管理员权限 → 不影响现有博客 → 不破坏现有 Admin → 不影响桌宠与其他功能。
