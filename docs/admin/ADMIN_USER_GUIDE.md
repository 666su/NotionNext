# 管理员使用指南 —— Jason Blog Admin（Phase 1）

---

## 1. 在哪里登录

浏览器打开：

```text
https://blog.20240606.xyz/admin
```

未登录会自动跳到 `/admin/login`。后台**不在**博客导航、页脚或文章中提供入口。

> 首次部署后第一次登录：用环境变量里的 `ADMIN_USERNAME` 与你自己设置的密码。登录成功后，密码哈希会被写入 Redis（`admin:user:<用户名>`），此后以 Redis 中的为准。

---

## 2. 第一次要做的事

1. 登录后进入 **系统设置**。
2. 立刻修改初始密码（要求：≥12 位、同时含字母与数字、不能包含用户名）。
3. 修改成功后所有会话失效 → 会跳回登录页，用新密码登录。
4. 在 **系统设置 → 审计日志** 确认能看到刚才的登录/改密记录。

---

## 3. 会话规则

| 规则 | 默认值 |
| --- | --- |
| 空闲超时 | 30 分钟无操作自动失效 |
| 绝对有效期 | 12 小时（到点必须重新登录） |
| 登录成功 | 旧会话被销毁，重新签发（防会话固定） |
| 改密 | 该账号所有会话立即失效 |
| 登出 | 服务端记录与浏览器 Cookie 同时清除 |

可在 Vercel 用 `ADMIN_SESSION_IDLE_MIN` / `ADMIN_SESSION_TTL_HOURS` 调整。

---

## 4. 登录安全

- 连续失败 **5 次**（15 分钟窗口）→ 冷却 15 分钟，返回“尝试次数过多”。
- 冷却**只作用于登录**，不影响你（或任何访客）访问公开博客。
- 不会永久锁死账号；冷却结束即可继续。
- 错误提示统一为“用户名或密码不正确”，不会暴露账号是否存在。
- 所有登录成功/失败都写入审计日志（含 IP 指纹与时间，不含明文 IP）。

如果被冷却卡住又急需登录：等 15 分钟，或在 Vercel 调整 `ADMIN_LOGIN_MAX_FAILS` / `ADMIN_LOGIN_WINDOW_MIN` 后重新部署。

---

## 5. 各页面现在能做什么

| 页面 | 状态 | 说明 |
| --- | --- | --- |
| 数据总览 | **可用（Phase 3）** | 今日/昨日/7 天/30 天卡片、实时活跃（估算）、访问趋势、来源、热门页面、文章表现 |
| 流量分析 | **可用（Phase 3）** | 时间范围切换、趋势/逐小时、页面排行、入口与退出、来源域名、搜索词、外链与分享 |
| 访客分析 | **可用（Phase 3）** | UV 趋势、设备/浏览器/系统/国家分布、首次访客与回访（单位是浏览，不是人数） |
| 行为分析 | **可用（Phase 3）** | 阅读深度直方图、完成率、文章深度表、搜索/外链/分享、事件计数 |
| 文章管理 | **可用（Phase 3/4）** | 文章阅读排行（筛选/排序）、分类与标签分布、**Notion 只读同步面板**（含冷却与日志） |
| 分类与标签 | **可用（Phase 4）** | 分类/标签的文章数与阅读量，来自 Notion 快照；后台不回写 Notion |
| 评论统计 | **可用（Phase 4，未配置时为"未连接"）** | 每篇评论数；刻意看不到待审核/垃圾评论（只用公开接口） |
| SEO 分析 | **可用（Phase 5，GSC 部分为"未连接"）** | 标题长度/摘要缺失/分类标签/更新新鲜度自查 + robots/sitemap 探测；GSC 未授权前不显示任何搜索指标 |
| 网站健康 | **可用（Phase 5）** | 存储与配置状态、部署环境、Notion 同步、首页/归档探针（3 分钟缓存）、失效链接检查（手动、10 分钟缓存） |
| 每日总结 | **可用（Phase 6）** | AI 浏览总结、日报预览、手动推送到 Telegram、查看发送日志 |
| 系统设置 | **可用** | 改密、查看会话存储类型、查看审计日志 |

**重要**：所有页面都**不会显示模拟数字**。看到“—”表示"该口径没有采集到数据"，看到 0 才是"确实是 0"。两者含义不同，不要混读。

## 6. 数据与隐私（本后台的承诺）

- 不采集：真实姓名、邮箱、手机号、明文 IP、精确 GPS、设备指纹、评论正文。
- 访客识别：仅用随机匿名 ID（浏览器第一方存储）+ 独立 Session ID。
- 审计日志：只记 `ipHash`（加盐哈希，不可反查）与 `uaHash`，不记明文。
- 统计保留：Phase 2 起，明细 1 小时、搜索词 30 天、日聚合 400 天（可配置）。

## 7. 常见问题

**Q：忘记密码了怎么办？**
A：管理员只有一个。用 `node scripts/admin-hash-password.mjs "新密码"` 生成新哈希，更新 Vercel 的 `ADMIN_PASSWORD_HASH` 后重新部署即可（Redis 里已有账户记录，会优先用 Redis 中的哈希 —— 若要强制覆盖，需要先删除 Redis 键 `admin:user:<用户名>`）。**注意：这条路径需要能访问 Vercel 与 Redis 控制台。**

**Q：为什么改完密码被踢出登录？**
A：设计如此。改密会销毁该账号全部会话，避免旧会话继续可用。

**Q：后台会不会拖慢博客？**
A：`/admin` 的代码不在公开页面加载路径上；`_app` 只多了一次 `pathname` 前缀判断。Phase 1 未引入任何公开页面脚本。

**Q：后台页面会被搜索引擎收录吗？**
A：不会。`/admin/*` 与 `/api/admin/*` 都下发 `X-Robots-Tag: noindex, nofollow`，且不进 sitemap。

**Q：能在手机上用吗？**
A：可以。侧边栏在窄屏折叠为抽屉，页面为桌面优先、移动可用。

**Q：审计日志里“IP 指纹”是什么？**
A：`sha256(IP | SESSION_SECRET)` 的前 24 位十六进制，仅用于同一来源的关联与限流，无法还原出 IP。

---

## 8. 安全建议

1. 密码用密码管理器生成，≥16 位。
2. 不要在公共电脑上保持登录；用完点“退出登录”。
3. 定期在“系统设置”翻一下审计日志，异常登录会留下 `login.failure` 记录。
4. `SESSION_SECRET` 只在 Vercel 环境变量里保存；如需轮换，所有会话会立即失效（可接受）。
5. 不要把 `/admin` 链接贴到公开地方（虽然它受保护，但少暴露无妨）。
